# CLAUDE.md

fukikae: Python CLI that dubs foreign-language TV into English. Spec and plan are in `docs/superpowers/`.

## Commands
- `uv sync`, `uv run pytest`, `uv run ruff check`, `uv run ruff format --check`, `uv run pyright`. uv only, never pip.
- Markers: `gpu`, `media` (need `FUKIKAE_TEST_MEDIA`; deselected by default), `ffmpeg` (needs only the binary), `slow`.
- ffmpeg/ffprobe come from mise (`.mise/config.toml`): `mise exec -- ffprobe -version`. Call them with argument lists.

## Rules
- Model code lives only in `src/fukikae/backends/<kind>/`; heavy backends are optional extras.
- Source media is read-only; work in the workspace.
- Conventional Commits.
- Identity profiles live in `src/fukikae/profiles/<name>.toml`, chosen by `profile = "anime" | "live-action" | "default"` in the workspace's `fukikae.toml`. Every table in a profile names its `backend` (`matcher` for `[characters]`), except `[tts]`, which holds only `clone_backend` (D41: `[tts] backend` chooses no card, so the profiles name none; its `[tts.<backend>]` sub-tables configure one backend each). Joint is not a stage matcher: `fukikae registry resolve` runs it and reads the profile's `[resolve]` table (`matcher`, `threshold`, matcher options; the selector is `matcher`, so `[resolve]` and `[characters]` are exempt from the `backend` rule); CLI flags override it. A profile's numbers come from tuning episodes only; see `docs/results/2026-11-07-identity-profiles.md` (anime, default) and `docs/results/2026-11-09-live-action-ground-truth.md` (live-action, which supersedes the 2026-11-07 live-action pick).
- Changing the embedder (backend, model, profile, or the WeSpeaker default for a workspace with no profile) means `fukikae registry reembed <workspace>` before diarize re-runs, then re-running the pipeline. reembed never recomputes a locked or exemplar-less centroid (Ruling R20): kept as stored at the same dimension, mapped by a ridge fit on exemplar pairs across a dimension change, refused with too few pairs. Dimension-mismatch errors point there; never tell a user to re-run diarize and rematch, which fails against the old-dimension registry.
- Voice cards (`src/fukikae/cards/`): a card's id hashes what it sounds like, and its defaults are frozen forever (Ruling CD1: a changed default is a new field, never a new value). Automatic assignment (`by = "auto"`, the tts stage via `cards.auto.ensure_assignments`) only fills characters with no card, with these exceptions: a stale automatic clone card (10% or more of a reference under another character's subtitle names, D29 #4) is re-picked at the next tts run, so is an automatic clone card under the clone floor (2 clips and 10 s, D32) when the current rules find a better pick (`cards.auto.below_floor`; with none it is kept and flagged), so is one with references the A1 reference gates refuse (`cards.auto.impure_cards`), so is an automatic clone card whose references are the other register from the character's operator gender (`GENDER_NOTE`, `re-picked: operator gender`, re-picked with the operator's class as the register), so is a pitch split keeper's automatic clone card with references 10% or more in another voice part's turns (`cards.auto.split_stale_references`), and so is an automatic stock card (`auto`, `auto-fallback`, `restock`; `cards.auto.stock_cards`, noted `STOCK_NOTE`); curated (`chosen_by = "studio"` included), locked and imported cards are only flagged; the registry refuses it, and imports, over a locked or operator-chosen card (CD2, CD3, CD9). New characters get a clone card of `[tts] clone_backend` (IndexTTS2 in every profile, D24) from `cards.select` references (fragments at most `JOIN_GAP_S`, 0.6 s, apart joined first; non-neutral turns only up to the floor; a clone under the floor is flagged), in three tiers (`cards.select.tiered_references`: floor, short from 3 s, thin below it from the longest turns, flagged); a character with no turn of its own is cloned thin from its own cues' spans, and extras and cluster-less lines get episode-local clones (`cards.auto.extras_cards`). Never a stock voice (D41): no pipeline path makes or assigns one (`tests/test_no_stock.py`); while the clone backend can't run (`cards.auto.clone_problem`: worker env, lock, no usable GPU; a device typo raises) or is unset, the tts stage refuses (`stages.tts.CloneBackendError`) before any model loads when a card must be made or re-picked or a clone render isn't cached. `[tts] backend` chooses no card (a workspace that sets it is warned); `voices assign stock:` and stock cards in pack imports are refused, `voices restock` is retired; Kokoro and the `stock` source stay for operator-kept stock cards and `eval tts` baselines (`fukikae.eval.stock` holds the pools).
- Cloning backends run as workers in their own uv projects (`workers/<name>`, `.venvs/<name>`, CD13); every GPU job holds the per-GPU flock (`fukikae.gpulock`, CD15). Nothing downloads at run time: models load from the local cache, `fukikae backends setup <name>` is the only fetch, and telemetry is off process-wide (CD24). A new backend declares a capability only with A/B evidence in the ledger (CD20).
- TTS post-processing (`stages/tts.py`): a render is trimmed (`trim_silence`) and gain-adjusted, then cached under `cue_key`; what plays is that render with internal pauses capped (`cap_pauses`, D33: `[tts] max_pause_ms` 200, `max_pause_ms_ellipsis` 500 for lines with "..." or "…", 0 off), cached beside it under `capped_key(key, cap)`. The cap is never in `cue_key`, `fitted_key` or `retry_key` (those derive from the uncapped render), so a cap change re-derives wavs without rendering; the rate fit, `SpeechRates` and the plan's `seconds` measure the capped wav, the render guards the uncapped one, and the stage key holds `pauses` only while the cap is on.
- `[tts] engines` maps a card backend to another backend that renders its cards (`card_backend`): `{ indextts2 = "indextts2_trt" }` is the only one, opt-in and off in every profile (D30), PyTorch IndexTTS2 the default. An engine makes no cards: it is refused as `clone_backend`, `[tts] backend` and `voices clone --backend`. It reads `[tts.<engine>]`, never the card backend's table; its renders are keyed by its own name and identity; `voices verify` and export fingerprints render on the card's own backend. indextts2_trt runs in a local Docker image (`workers/indextts2_trt`, never pushed; setup about 24 GB of image, 3 GB of engines plus 5 GB of intermediates, about 40 minutes the first time); with it configured and Docker unusable a run fails with `BackendUnavailable`, never a silent PyTorch fallback (F5). Its containers pass `FUKIKAE_GPU_INDEX`, which `gpulock`'s leftover scan reads before `CUDA_VISIBLE_DEVICES`.
- The subtitle path (`[translate] source = "auto"`) reads only a dialogue subtitle track (`media.dialogue_track`, CD25): never forced, or signs/songs without full/dialogue/complete, by title, never a track too sparse for dialogue against the densest unflagged track; a forced flag is ignored only at 8 cues a minute or more.
- Subtitle speaker names (D27, `src/fukikae/names/`): names win over acoustics for the speech they cover, and disagreements are reported, never acted on; locked actors and characters, operator names and operator aliases win over names. `[names]` is a settings table exempt from R3 like `[resolve]`. The pipeline reads registry aliases only; eval reads `labels-aliases.yaml`. Held-out episodes and hidden lines are invisible to every pipeline consumer, and every eval path that grades a held-out episode calls `names.inputs.check_held_out` first (its `names.json` and its assignments); an episode graded on names it read is reported only as a ceiling.
- Run progress (#29, `fukikae.progress`): `job.run_stages` wraps each stage in `progress.stage`, and a long stage reports through `progress.start(total, unit)` / `advance` / `set_done` / `finish`, which do nothing outside `fukikae run` (no reporter open), so stages called directly (tests, eval) are unchanged. Progress never touches a stage's outputs or cache key, and a reporter failure never raises into a stage or a log call (every entry point catches, logs at debug once and degrades). Each run writes `.fukikae/runs/<host>-<pid>.json` (read by `fukikae status`, live by pid on this host and by the age of `updated` on another) and `.fukikae/stage-history.json` (ETAs, under a file lock); the reporter keys its slots by thread role (`head`, or `tail` for D26's `fukikae-tail` thread). `gpulock` reports waits and holds to it, and logs `waiting for GPU N, held by pid P (<what>) for <dur>` at once and every `WAIT_LOG_S` (60 s), the holder's time taken from the lock file's mtime.
- Pitch (A0, spec approved under D40): every voice-register decision reads `fukikae.pitch` and nothing else (window-corrected autocorrelation, 60 to 800 Hz; `classify` bands the median: `m` under 165 Hz, `f` over 200 Hz, else `u`, and `u` under 1.0 s voiced for a speaker or 0.4 s for a line). Tracks are cached in `.fukikae/pitch-cache/` keyed by the vocals' sha256, spans, groups and `pitch.VERSION`; any change to what `f0_track` returns bumps `VERSION`. "Gender" everywhere means voice register as heard, never the character's gender in the story. The estimate is never stored in the registry.
- No wrong-gender emotion prompt on any path (A3, D41): `stages.tts.delivery_passed` passes no `emotion_audio` for a source line in the other band from its speaker's established gender (the operator gender, else the speaker's own turns by the 2x rule), so tts, `eval ab` and studio auditions share the rule; the line renders in the speaker's own card, `gender_gate = true` in the plan. A narrator's other-band lines also pass no emotion audio, unflagged.
- `asrclean` (`03b-asrclean/`, A4) drops stock outro hallucinations over theme songs, sung music or no speech, on the CPU, never rerunning ASR. Every consumer reads the transcript through `fukikae.transcripts.transcript_path` (the cleaned one, else `03-asr/transcript.json` with a warning); never open `03-asr/transcript.json` directly.
- Registry schema 5: `characters.gender` (`f`, `m`, NULL), `gender_by` (`operator`; `cast` is reserved and nothing writes it), `kind` (`character`, `narrator`, `ignored`), `reviewed`, plus `decision_marks` and `review_evidence` (both joined schema 5 unreleased, no version bump). `OPERATOR_BY` includes `studio`. An operator gender or a non-default kind counts as curation (the actor survives `rematch` and `resolve` pruning), but an operator gender alone never stops subtitles naming an unnamed character.
- Operator state beats every automatic rule: an operator gender beats the pitch estimate in A1's register gate (name-confirmed turns included, gated by class only), in A3's established gender and in auditions; a cast gender is only an offer, and applying it stores `gender_by = "operator"`. A narrator gets its own card, no one-scene reference gate and no A3 flag, and is never a merge suggestion beside a dialogue character. An ignored character's clusters are matched and pinned as usual but written `status = "ignored"`, and its cues `skip = "ignored"` (never translated or rendered, the mix keeps the original vocals): the only way a speaker gets no clone, and only by the operator. `registry gender` marks tts stale for the character's episodes, `registry kind` marks characters stale.
- The studio's one writer is `fukikae.studio.apply` (`apply_decision`, `apply_file`, `resume_incomplete`): the page, `fukikae studio apply <ws> FILE` and scripts all go through it, one `Registry.transaction()` per decision. Decisions are pydantic models discriminated on `op` (`name`, `alias`, `gender`, `merge`, `split`, `kind`, `lock`, `reviewed`, `accept`), each carrying `digest` (`row_digest`: the character and its actor; for `accept` the language's card assignment only; for `merge` both characters), plus `key` and `external_id`. A changed digest is `StaleDecision`, a missing one `UncheckedDecision`; `--force` skips the digest check for every decision in the file and the CLI counts them. A registry refusal (`ValueError`, `KeyError`, `CardError`) is `DecisionRefused` with nothing changed. A file stops at its first refusal, earlier decisions staying applied; `--dry-run` checks the whole file in one rolled-back transaction and never creates or migrates a registry. Every identity decision marks its characters reviewed; `reviewed` marks without change.
- Decision records (`<ws>/studio/decisions.jsonl`, W1, R1, R2): inside the transaction a `decision_marks` row and a write-ahead record (`incomplete: {left: <every step>, pending: true}`, fsynced) go in before COMMIT; after it, stale marks first, then file changes (assignments remapped, a split file), then a completion record (`completes`), written on Ctrl-C too, naming errors and steps left (`IncompleteDecision`: the registry part landed). A pending record without its mark row is closed `aborts` (nothing to redo); with it, `fukikae studio resume` redoes what is left (`resumes`). Replays are decided by `decision_marks`, never the log alone. A line that isn't a record is `LogUnreadable`, refused with its line number until repaired. `registry merge` and `registry split` write the same records; a merge remaps and invalidates the drop character's episodes (`registry.invalidate.merge_episodes`, I1).
- Run guard and run lock (W3, R3): while any record is unfinished, `studio apply`, `registry merge`/`split` and any `fukikae run` whose stages through `--to` include names or later (`job.ASSIGNMENT_STAGES`) refuse and name `fukikae studio resume`. Writers take `studio/.lock` exclusively without waiting (name and pid in the file) and are refused naming the holder; `job.run_stages` holds it shared (only when `studio/` exists). `registry` rename, alias, lock, kind and gender run under it too. A stage marked stale while it ran is not recorded done (`Manifest.stale`).
- `fukikae studio [options] <ws>` (`serve`; `--port 8765`, `--clips 6`): binds 127.0.0.1 only (`--allow-non-loopback` takes one IPv4 interface address, never 0.0.0.0, which becomes the only allowed Host), prints `http://127.0.0.1:<port>/#t=<token>` and `ssh -L <port>:127.0.0.1:<port> <host>`, opens no browser. The token lives only in the URL fragment; the page keeps it in sessionStorage and sends `X-Fukikae-Token` on every `/api`, `/audio`, `/video` and `/audition` request (media fetched into blob URLs). No cookie, no `?t=` anywhere; `/` and `/static/*` serve the data-free shell without a token. Host and Origin are checked, bodies capped at 1 MB, handlers time out after 30 s, at most 16 at once, unexpected failures are 500 `{"error":"internal"}`, and served files are opened component by component with `O_NOFOLLOW`. The page itself is pending the operator's design pick (D47; no `app.js`): today the API and `fukikae studio apply` are the interface.
- Pitch splits (Task 15): a `split` decision with `by = "pitch"` writes `<ws>/studio/splits/<episode>.json` (`{cluster: {by, male_below, female_above, fingerprint: {turns, seconds, sha256}}}`); the names stage relabels the cluster's unnamed turns `<cluster>~voice-f` / `~voice-m` by each turn's own median (`u` to the larger part), the file's digest in its key. Only a diarize cluster, never a `~` sub-cluster; a changed fingerprint skips the split (`check = "changed"`, season flag `split`), a fingerprint-less file applies as `unchecked`. `by = "cluster"` is `split_cluster` (characters stale).
- Identities after a pitch split (Task 15 rulings): a voice part never inherits its parent's pin. A part with an identity of its own (its own earlier label pin, an operator merge or remap, a name, a lock) keeps it in characters reruns, `--rematch` and `registry resolve`. Only for parts without one does the keeper rule decide: exactly one part keeps the parent's character, the part in the stored operator gender, else the longer (`~voice-f` on a tie); a non-keeper keeps its match to another existing character, else gets a new actor and character (`split = "new"`, season flag `identity` until reviewed), rowless or not. A later stored gender never moves a part (the index flags `gender` instead).
- Voice drafts and accept (Task 18 rulings, D41): `<ws>/studio/drafts/<character>.<language>.json`; version 1 from the current clone card, else derived from a studio-accepted (then other operator-chosen) clone card of another language, else the automatic proposal, assigned nowhere; never from a stock, imported or automatic card for another language. Version 1 is never refused but records `acceptable` and `accept_problems`; every later version is held at draft time to accept's rule (422): each reference inside the character's own turns and overlapping no other speaker, whatever its seconds; cue spans count only in an episode where the character has no turns; no duplicate or overlapping references, at most 12 s each; a reference in an episode whose names or characters stage is stale or older than a studio decision on the character is refused ("run `fukikae run <ws> <ep> --to characters` first"). The one exemption is exactly the reference set of a thin card the pipeline built for the character, recorded as `thin_origin` on the version and the card's `[meta]` and checked against card history at accept, never `reference_tier` alone. Accept takes only `source = "clone"` and assigns `chosen_by = "studio"`, locked, its note naming the draft version, references, overrides and audition count; `/api/decisions` refuses a raw accept (use `.../accept`).
- Auditions (`studio/audition.py`, Task 19): one worker thread, FIFO, at most 16 queued; real lines render through the tts stage's own path (`prepare_cue`, `delivery_passed`, `render_line`, the pause cap) into the tts cache under the stage's `cue_key`, so accepted lines are already rendered. It holds the GPU lock only while a model is loaded (taken on the first uncached render, released at once by a job that stops before loading, on `AUDITION_IDLE_S` 300 s idle, `/api/gpu/release` and server close); a load waits at most `AUDITION_VRAM_S` (120 s) for VRAM. Only the version's own backend and only clone cards; no fallback.
- `[review]` (Task 21; a settings table exempt from R3, left out of the season index's config digest): `identity` (stop before translate), `voices` (stop before tts), both off in every profile, `min_seconds` 30.0 (finite). A main character is kind `character` or `narrator` with `min_seconds` of speech in the episode. `identity` stops for one never reviewed, with names flags whose digest (`names.flags.names_flag_digest`, over flag identities, never wording) differs from the one its review recorded in `review_evidence`, or an impure automatic card assigned after the review. Split suggestions never stop a run (notes only). `voices` stops for one without a curated, imported or locked card in the target language, or with a stock card (D41). A stop exits 3 (only when nothing failed), names `fukikae studio <ws>` and `fukikae studio apply <ws> FILE` once, and is `stopped` in `fukikae status`, never `failed`; other episodes go on.
- `<ws>/cast.toml` (Task 22, `[[cast]]` with `name`, `gender`, `external_id`, `aliases` only; unknown keys fail with the line, voice keys refused under D41): read only by the studio, never by names, identity or eval. Matches by external id, then name or alias (skipped when both carry different ids; ambiguity marked); a cast gender is offered only when no operator gender is stored, never applied without a click; cast aliases never become registry aliases.
- Studio files under `<ws>/studio/`: `season.json` (the derived index, never edited, rebuilt when its inputs digest changes), `audio/` (24 kHz mono sample clips), `video/` (H.264 CRF 28, 480 px wide, 96k AAC sample clips, cut on first `GET /video/<sha>.mp4`, at most 2 at once), `auditions/` (and `auditions/ref/`), `drafts/`, `splits/`, `decisions.jsonl`, `.lock`; `audio/`, `video/`, `auditions/` and `drafts/` are 0700, re-chmodded on use. A video needs the workspace's `source` setting to find the file the extract stage read (its cache key must match), else `EpisodeEntry.video_note`. Known limitations (spec, left as they are): a cut finishing after a rebuild pruned its name leaves an orphan clip until the next rebuild; writes follow a symlinked `studio/` though reads refuse one; a source replaced with the same size and mtime keeps its clip names; an audition on a backend that takes a speaking rate may key a later line differently from the stage (IndexTTS2 takes none); a cleared operator gender gets the cast offer again.
