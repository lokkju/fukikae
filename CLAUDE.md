# CLAUDE.md

fukikae: Python CLI that dubs foreign-language TV into English. Spec and plan are in `docs/superpowers/`.

## Commands
- `uv sync`, `uv run pytest`, `uv run ruff check`, `uv run ruff format --check`, `uv run pyright`. uv only, never pip.
- Markers: `gpu`, `media` (need `FUKIKAE_TEST_MEDIA`; deselected by default), `ffmpeg` (needs only the binary), `slow`.
- ffmpeg/ffprobe come from mise (`.mise/config.toml`): `mise exec -- ffprobe -version`. Call them with argument lists.

## Rules
- Model code lives only in `src/fukikae/backends/<kind>/`; heavy backends are optional extras.
- Source media is read-only; work in the workspace.
- Conventional Commits.
- Identity profiles live in `src/fukikae/profiles/<name>.toml`, chosen by `profile = "anime" | "live-action" | "default"` in the workspace's `fukikae.toml`. Every table in a profile names its `backend` (`matcher` for `[characters]`). Joint is not a stage matcher: `fukikae registry resolve` runs it and reads the profile's `[resolve]` table (`matcher`, `threshold`, matcher options; the selector is `matcher`, so `[resolve]` and `[characters]` are exempt from the `backend` rule); CLI flags override it. A profile's numbers come from tuning episodes only; see `docs/results/2026-11-07-identity-profiles.md` (anime, default) and `docs/results/2026-11-09-live-action-ground-truth.md` (live-action, which supersedes the 2026-11-07 live-action pick).
- Changing the embedder (backend, model, profile, or the WeSpeaker default for a workspace with no profile) means `fukikae registry reembed <workspace>` before diarize re-runs, then re-running the pipeline. reembed never recomputes a locked or exemplar-less centroid (Ruling R20): kept as stored at the same dimension, mapped by a ridge fit on exemplar pairs across a dimension change, refused with too few pairs. Dimension-mismatch errors point there; never tell a user to re-run diarize and rematch, which fails against the old-dimension registry.
- Voice cards (`src/fukikae/cards/`): a card's id hashes what it sounds like, and its defaults are frozen forever (Ruling CD1: a changed default is a new field, never a new value). Automatic assignment (`by = "auto"`, the tts stage via `cards.auto.ensure_assignments`) only fills characters with no card, with three exceptions: a stale automatic clone card (10% or more of a reference under another character's subtitle names, D29 #4) is re-picked at the next tts run, so is an automatic clone card under the clone floor (2 clips and 10 s, D32) when the current rules find a better pick (`cards.auto.below_floor`; with none it is kept and flagged, never made stock), and an `auto-fallback` stand-in is upgraded when cloning works; curated, locked and imported cards are only flagged; the registry refuses it, and restock and imports, over a locked or operator-chosen card (CD2, CD3, CD9). New characters get a clone card of `[tts] clone_backend` (IndexTTS2 in every profile, D24) from `cards.select` references (fragments at most `JOIN_GAP_S`, 0.6 s, apart joined first; non-neutral turns only up to the floor; a clone under the floor is flagged), or a stock voice under 6 s of clean speech; while the clone backend can't run (`cards.auto.clone_problem`: worker env, lock, no usable GPU; a device typo raises) the stand-in is `auto-fallback`, which the next usable run upgrades to a clone; `[tts] backend` stays the stock and extras backend.
- Cloning backends run as workers in their own uv projects (`workers/<name>`, `.venvs/<name>`, CD13); every GPU job holds the per-GPU flock (`fukikae.gpulock`, CD15). Nothing downloads at run time: models load from the local cache, `fukikae backends setup <name>` is the only fetch, and telemetry is off process-wide (CD24). A new backend declares a capability only with A/B evidence in the ledger (CD20).
- `[tts] engines` maps a card backend to another backend that renders its cards (`card_backend`): `{ indextts2 = "indextts2_trt" }` is the only one, opt-in and off in every profile (D30), PyTorch IndexTTS2 the default. An engine makes no cards: it is refused as `clone_backend`, `[tts] backend` and `voices clone --backend`. It reads `[tts.<engine>]`, never the card backend's table; its renders are keyed by its own name and identity; `voices verify` and export fingerprints render on the card's own backend. indextts2_trt runs in a local Docker image (`workers/indextts2_trt`, never pushed; setup about 24 GB of image, 3 GB of engines plus 5 GB of intermediates, about 40 minutes the first time); with it configured and Docker unusable a run fails with `BackendUnavailable`, never a silent PyTorch fallback (F5). Its containers pass `FUKIKAE_GPU_INDEX`, which `gpulock`'s leftover scan reads before `CUDA_VISIBLE_DEVICES`.
- The subtitle path (`[translate] source = "auto"`) reads only a dialogue subtitle track (`media.dialogue_track`, CD25): never forced, or signs/songs without full/dialogue/complete, by title, never a track too sparse for dialogue against the densest unflagged track; a forced flag is ignored only at 8 cues a minute or more.
- Subtitle speaker names (D27, `src/fukikae/names/`): names win over acoustics for the speech they cover, and disagreements are reported, never acted on; locked actors and characters, operator names and operator aliases win over names. `[names]` is a settings table exempt from R3 like `[resolve]`. The pipeline reads registry aliases only; eval reads `labels-aliases.yaml`. Held-out episodes and hidden lines are invisible to every pipeline consumer, and every eval path that grades a held-out episode calls `names.inputs.check_held_out` first (its `names.json` and its assignments); an episode graded on names it read is reported only as a ceiling.
