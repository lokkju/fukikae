fukikae studio

The studio page is pending: its design waits on the operator's pick (D47). The server, the JSON API and audio and video serving are running; this placeholder lists the API.

The token printed at start-up rides in this page's address after #t=, a part of the URL a browser never sends to a server. /static/token.js moves it into this tab's session storage and clears it from the address bar; every /api, /audio and /video request then sends it as the X-Fukikae-Token header, and audio and video are fetched with that header and played from a blob URL. There is no cookie and no token in a query string. This page and /static/ need no token and hold no data. POST bodies are JSON (1 MB at most).

A hand-written cast.toml in the workspace ([[cast]] entries with name, gender, external_id and aliases) arrives in the season index as suggestions only: the cast list (cast, or cast_error when the file can't be read) for the name field and the queue header, and per character the entry it matches (cast), whose gender, when offered, is one gender decision away. Nothing from it is applied without that decision.

Routes

  • GET /: this page (no token needed).
  • GET /static/<file>: the page's files, from the package only (no token needed).
  • GET /api/season: the season index (SeasonDoc), rebuilt when its inputs changed.
  • GET /api/characters/<id>: one character's entry (CharacterEntry).
  • GET /audio/<sha256>.wav: a clip the index refers to (a sample's clip). One Range: bytes= range gets 206, one starting past the end 416; any other Range form gets the whole clip.
  • GET /video/<sha256>.mp4: a sample's video clip (its video: picture and the source-language audio, H.264 and AAC, 480 px wide), only for names the index refers to, cut by the server on first fetch. Ranges as for /audio. A sample has no video when its episode's source file can't be found or has no picture; the episode's video_note says why.
  • POST /api/decisions/preview: a dry run of an identity decision: what it would rerun, whether its digest is stale or missing, and the decision with its digest filled in (decision), to post as previewed; writes nothing.
  • POST /api/decisions: apply an identity decision (every op but accept); returns the rebuilt character. 409 when stale or unfinished, 422 when refused or carrying no digest, 423 while a run or another writer holds the studio lock.
  • GET /api/characters/<id>/candidates: the character's reference candidates (its own speech only), each with its rank, gate verdicts and reasons, a page at a time: ?offset=, ?limit= (200 at most), ?gated=1 to include the refused turns. A candidate's clip is cut when first fetched from /audio.
  • GET /api/drafts/<id>/<lang>: the character's voice draft for a target language, opened (version 1 from its current card, an accepted card of another language, or the automatic proposal) when it has none; with the meter and the clip of each reference.
  • POST /api/drafts/<id>/<lang>/versions: a new version from {references, backend, params}: its card id, the gated references chosen anyway (overrides) and the meter. 422 for a voice key the backend lacks or a reference that isn't the character's own speech. Writes no registry row.
  • GET /api/drafts/<id>/<lang>/compare: two versions of the saved draft on one line, ?a=<n>&b=<n>&line=<line> (line the URL-encoded JSON of an audition line, as POST /api/auditions takes it). A version with no audition of that line gets one queued (auditions pair by line, never by cue key); the page polls until both sides are done. Each side has its state, wav_url, version, job and audition; source_clip is a real line's source span under /audio. &blind=1 labels the sides A and B (queued in that order; the labels hold for that pair and line until the server stops) and answers one state for the pair (rendering until both sides are done, then ready, or failed) with a generic message; each side has only its wav_url, an opaque alias under /audition, and only once the pair is ready. Nothing in a blind answer names a version, card, backend or render key, its refusals included. &retry=1 queues a failed side again; without it a failed side stays failed. HEAD queues nothing. 400 for a bad query or the same version twice, 404 for no saved draft or version, 409 when the draft file can't be read (or is another character's or language's), 422 when the line can't be auditioned, 503 when the queue is full.
  • POST /api/drafts/<id>/<lang>/reveal: a blind compare's key, {a, b, line} to {key: {A: <n>, B: <n>}}.
  • POST /api/drafts/<id>/<lang>/accept/preview: a dry run of accepting a saved version, {version, card_id}: the accept decision the server built, what reruns, stale or unchecked when the apply would refuse it for that, and cached: per episode whose tts goes stale, the character's lines already in the tts cache with the version's card under the workspace's config as it is now (null with cached_error when that can't be worked out). Refuses as the accept does. Writes nothing.
  • POST /api/drafts/<id>/<lang>/accept: accept a saved version, {version, card_id} (card_id the version's card as the page showed it), as the character's card for the language (studio, locked: curated from then on). The decision is built here from the version (its card, references, overrides, audition count, and the digest of the language's card assignment taken when the version was made), so a raw accept is never posted to /api/decisions. Answers as POST /api/decisions does, plus cached. 409 when the card assignment changed since the version was made (a tts run re-picked it, or another accept), or version-changed when the version is another card than card_id (the draft was opened again since); 422 when accept refuses the version (the draft's accept_problems, rechecked here: not the character's own clean speech, D41, or audio named more than once) or the version records no digest; 423 while a run or another writer holds the studio lock.
  • GET /api/backends: the clone backends and each one's voice keys, with type and range, and whether it can run here (checked false until the check, run in the background, has answered).
  • POST /api/auditions: queue an audition of a draft version on a line, {character, language, version, line}, where line is {kind: "real", episode, cue_id} (one of the character's translated cues, rendered as the tts stage renders it) or {kind: "typed", text, emotion_from} (emotion_from: an optional {episode, cue_id} whose source span is the emotion prompt, under the line gate). 202 with the job; 404 for no such draft or version, 422 when its backend can't render here (never another backend or a stock voice), 503 when the queue is full.
  • GET /api/auditions/<job>: an audition job: queued, waiting (for the GPU), loading, running, done (its audition, wav_url and, for a line with a source span, source_clip under /audio), failed (its message) or cancelled.
  • POST /api/auditions/<job>/cancel: cancel a job (a render already running finishes into the cache).
  • GET /api/gpu: the audition worker: the backend loaded, its device, what it is doing, who holds the GPU (holder), the jobs queued and when an idle model unloads.
  • POST /api/gpu/release: cancel the queued and waiting auditions, unload the model and let go of the GPU.
  • GET /audition/<key>.wav: an audition's audio (a job's wav_url, or a wav a draft's version lists). Ranges as for /audio.
